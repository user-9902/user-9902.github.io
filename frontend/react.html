React ​

什么是 React ​

React 是用来快速开发用户界面的MVVM框架。React 带来了虚拟DOM、组件、JSX等概念。React的出现标志着前端开始朝着工程化、框架化发展。

React 的特性 ​

  • 声明式：描述“是什么”，而非“怎么做”，解决复杂 UI 状态下的不可预测性和难调试
  • 组件化：UI 拆分为独立可复用的零件 代码复用、大型项目协作和维护
  • JSX：JS 里写类 HTML 标签 提升 UI 组件编写时的直观性和开发体验
  • 虚拟DOM：内存中的轻量级 UI 表示，解决高频交互场景下的浏览器性能瓶颈
  • 单向数据流：父传子，子通知父，混乱且难以追踪的数据变更（Bug之源）
  • Hooks：函数组件中使用状态和副作用 类组件的复杂、逻辑复用困难
  • 跨平台：React DOM / React Native 一份代码，多端运行

MVVM ​

MVVM 是 model-view-viewmodel 的缩写。其中：

  • model 即模型（或数据模型），存储着的状态数据；
  • view即视图（或数据表现），即向用户展示的结构、布局、外观；
  • viewmodel即视图模型，视图层和模型层之间借助viewmodel进行沟通，viewmodel监听model层的数据变化，将变化展示在view层，同时viewmodel监听view层用户的交互事件、视图的变化以通知model层。vue中的mvvm是双向绑定的，视图层的变化数据将同步到model，model数据的变化也会立即响应到view上。

区别于MVC架构，MVC架构中，需要开发者书写大量的controller来主动的去维护view和model两者的关系。mvc架构中大量的controller代码，使得系统复杂度高，大量的DOM操作使用户体验差。MVVM架构中的VM（viewmodel）是controller的演进，能自动维护view和model的关系，降低系统复杂度，抽离出业务逻辑，使得开发者更加的专注于业务逻辑开发。

声明式 ​

用代码直接描述最终想要的效果，而非命令式的一步步去实现。

jsx
// 命令式 用dom api 去一步步的指挥该怎么做
const testEl = document.getElementById("test");
let num = 0;
setInterval(() => {
  testEl.textContent = String(num++);
});

// 声明式 直接描述好model层和view层之间的关系
function Counter() {
  // model
  const [num, setNum] = useState(0);

  useEffect(() => {
    const timer = setInterval(() => {
      setNum((prev) => prev + 1);
    }, 1000);
    return () => clearInterval(timer);
  }, []);

  // view
  return (
    <div>
      {num} {/* 声明好view层和model层间的关系 */}
    </div>
  );
}
// 申明式

组件化 ​

React 将数据逻辑、视图逻辑、样式，整合到一起作为组件。组件就像是积木，每个组件负责页面中的一部分功能，通过组合、嵌套构成完整的页面。组件化提升了代码的复用性、可维护性。

jsx
// 一个简单的组件，将视图与逻辑封装在一起
function UserCard({ name, avatar, bio }) {
  return (
    <div className="user-card">
      <img src={avatar} alt={name} />
      <h3>{name}</h3>
      <p>{bio}</p>
    </div>
  );
}

// 组件的组合嵌套
function UserList({ users }) {
  return (
    <div className="user-list">
      {users.map((user) => (
        <UserCard key={user.id} {...user} />
      ))}
    </div>
  );
}

JSX ​

单纯的通过js来描述ui需要使用 React.createElement 来实现；单纯的通过xml来描述 ui 又无法直接声明好 view 与 model 之间的关系。因此 React 采用 js+xml 的语法来描述 ui 即jsx。 jsx本质上是通过js来描述ui的语法糖。最终jsx文件会被babel（swc）翻译为js文件。

jsx
// jsx 文件转义前
import React from "react";

const Example = ({ name, age }) => {
  return (
    <div className="greeting">
      <h1>Hello, {name}!</h1>
      <p>You are {age} years old.</p>
      <button onClick={() => console.log("Clicked!")}>Click me</button>
    </div>
  );
};

// babel 转移后
export default Example;
("use strict");

var _react = _interopRequireDefault(require("react"));

function _interopRequireDefault(obj) {
  return obj && obj.__esModule ? obj : { default: obj };
}

var Example = function Example(_ref) {
  var name = _ref.name,
    age = _ref.age;
  return /*#__PURE__*/ _react.default.createElement(
    "div",
    { className: "greeting" },
    /*#__PURE__*/ _react.default.createElement(
      "h1",
      null,
      "Hello, ",
      name,
      "!"
    ),
    /*#__PURE__*/ _react.default.createElement(
      "p",
      null,
      "You are ",
      age,
      " years old."
    ),
    /*#__PURE__*/ _react.default.createElement(
      "button",
      {
        onClick: function onClick() {
          return console.log("Clicked!");
        }
      },
      "Click me"
    )
  );
};

exports.default = Example;

虚拟dom ​

虚拟dom是用来描述真实dom的，两者一一对应，虚拟dom借助render函数转化为真实dom。虚拟dom的存储开销更小、书写简便，我们通过操作虚拟dom来间接操作真实dom。同时虚拟dom使得react能够在底层优化dom操作，提升性能；还使得react不局限于浏览器环境。

单向数据绑定 ​

React 中的数据流动是单向的，数据从父组件通过 props 向下传递给子组件，而子组件不能直接修改父组件的数据，只能通过回调函数通知父组件去修改。这种单向的数据流使得数据的变更路径可追踪、可预测，避免了双向绑定中数据变化来源不清晰、难以调试的问题。

jsx
// 父组件将数据和方法通过 props 传给子组件
function Parent() {
  const [value, setValue] = useState("");

  // 子组件通过调用父组件传入的回调来"通知"父组件修改数据
  return <Child value={value} onChange={setValue} />;
}

// 子组件只能读取 props，不能直接修改
function Child({ value, onChange }) {
  return (
    <input
      value={value}
      onChange={(e) => onChange(e.target.value)} // 通知父组件，而非自己修改
    />
  );
}

jsx
// 类组件
class Counter extends React.Component {
  constructor(props) {
    super(props);
    this.state = { count: 0 };
  }

  componentDidMount() {
    console.log("组件挂载完成");
  }

  render() {
    return (
      <div>
        <p>{this.props.title}: {this.state.count}</p>
        <button onClick={() => this.setState({ count: this.state.count + 1 })}>
          +1
        </button>
      </div>
    );
  }
}

// 函数组件（hooks）
function Counter({ title }) {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log("组件挂载完成");
  }, []);

  return (
    <div>
      <p>{title}: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}

组件生命周期 ​

类组件：

  • 组件创建阶段

    • constructor：类组件实例创建的时候执行
    • getDerivedStateFromProps：是一个静态的方法，不能访问到组件实例，该函数需要返回一个对象作为新 state 或返回 null 表示无需更新 state
    • render：类组件必须有的方法，该方法返回虚拟dom
    • componentDidMount：组件完成创建

  • 组件更新阶段

    • getDerivedStateFromProps
    • shouldComponentUpdate：该方法需返回一个boolean值，用于控制是否继续后续的更新组件流程。
    • render
    • getSnapshotBeforeUpdate：render执行后，真实dom更新前执行
    • componentDidUpdate：组件完成更新

  • 组件卸载阶段

    • componentWillUnmount：清除一些监听事件，取消订阅等清理工作。

函数组件：

函数组件没有类组件那样的生命周期方法，而是通过 useEffect 来模拟对应的能力。useEffect 的执行时机是真实 DOM 更新完成后（等同于 componentDidMount + componentDidUpdate），通过依赖数组和清理函数的组合来覆盖各阶段：

类组件生命周期函数组件等效写法
componentDidMountuseEffect(() => {}, [])
componentDidUpdateuseEffect(() => {}, [dep1, dep2])
componentWillUnmountuseEffect(() => { return () => {} }, [])
shouldComponentUpdateReact.memo(Component, (prevProps, nextProps) => boolean)
getSnapshotBeforeUpdateuseLayoutEffect(() => {}, [dep])（render 后、真实 DOM 更新前执行）

组件间通讯 ​

  • 父组件 → 子组件：props；useImperativeHandle + ref父组件主动调用子组件的方法
  • 子组件 → 父组件：callback props
  • 祖先 → 后代：Context（useContext）
  • 兄弟间/全局：状态管理库（zustand、redux）或事件总线（mitt）

受控组件/非受控组件 ​

表单元素通过 value（或 checked）+ onChange 来双向绑定状态，表单值的变化始终由 React state 驱动，即为受控组件。所有状态变更都通过 setState 触发，数据流完全可追踪。

非受控组件则不绑定 state，表单元素自己维护内部状态，需要通过 ref 来手动获取表单元素的值。

jsx
// 受控组件：值由 state 驱动，变更通过 onChange 同步回 state
function ControlledInput() {
  const [value, setValue] = useState("");

  return (
    <input
      value={value}
      onChange={(e) => setValue(e.target.value)}
    />
  );
}

// 非受控组件：值由 DOM 自身维护，通过 ref 获取
function UncontrolledInput() {
  const inputRef = useRef(null);

  const handleSubmit = () => {
    console.log(inputRef.current.value); // 需要时通过 ref 读取
  };

  return <input ref={inputRef} defaultValue="默认值" />; // defaultValue 仅设置初始值
}

Hooks ​

Hooks 是 React 16.8 引入的特性，让函数组件能够使用状态、副作用等能力。Hooks 本质是一组函数，必须遵循以下规则：

  • 只在函数组件或自定义 Hook 中调用，不能在普通函数、类组件中调用
  • 只在顶层调用，不能在循环、条件或嵌套函数中调用（React 依靠调用顺序来匹配 Hook 与 state）

useReducer ​

用于管理复杂数据类型的状态，是 useState 的替代方案。适合状态逻辑复杂、依赖前一个状态、或多个子值需要一起更新的场景。

jsx
const [state, dispatch] = useReducer(reducer, initialState, initFn?);

function reducer(state, action) {
  switch (action.type) {
    case "INCREMENT":
      return { ...state, count: state.count + 1 };
    case "DECREMENT":
      return { ...state, count: state.count - 1 };
    default:
      return state;
  }
}

并发渲染 ​

useTransition ​

将状态更新标记为"过渡"（低优先级），React 会优先处理更高优先级的更新（如输入），避免页面卡顿。

jsx
const [isPending, startTransition] = useTransition();

// isPending：过渡是否正在进行
// startTransition：将内部的 setState 标记为低优先级
function handleChange(e) {
  // 高优先级：输入框立即响应
  setInputValue(e.target.value);
  // 低优先级：搜索结果可以延迟更新
  startTransition(() => {
    setSearchQuery(e.target.value);
  });
}

副作用 ​

useEffect ​

在真实 DOM 更新后执行副作用。通过依赖数组和清理函数的组合，可以模拟类组件的 componentDidMount、componentDidUpdate、componentWillUnmount。

jsx
useEffect(setup, dependencies?);
// 依赖数组：
//   不传 —— 每次渲染后都执行
//   []   —— 仅挂载时执行一次
//   [a]  —— a 变化时执行
// 返回函数 —— 卸载或依赖变化前执行（清理副作用）

useEffect(() => {
  const subscription = subscribe(id);
  return () => subscription.unsubscribe(); // 清理
}, [id]);

useMemo ​

缓存计算结果，仅在依赖变化时重新计算。避免每次渲染都执行昂贵的计算。

jsx
const cachedValue = useMemo(() => expensiveCompute(a, b), [a, b]);

缓存函数引用，仅在依赖变化时重新创建。避免子组件因接收到新的函数引用而不必要地重渲染。

const memoizedCallback = useCallback(() => {

Fiber 架构 ​

为什么需要 Fiber ​

浏览器中 JS 是单线程的，且 JS 线程与渲染线程互斥。当有大量 JS 任务执行时，渲染线程会被阻断，导致页面卡顿。React 16 之前采用递归的方式处理组件树（Stack Reconciler），一旦开始就无法中断，长任务会长时间占据主线程，造成掉帧。

为此 React 16 重写了协调引擎，将渲染工作拆分为多个小任务单元（Fiber），实现可中断、可恢复、可优先级调度的增量渲染。这种主动进行任务调度的方式属于协程的一种，在 React 中被称为 Fiber（纤程）。

Fiber Tree ​

每个 React 元素对应一个 Fiber 节点。虚拟dom是树状结构，但为了能随时中断和恢复遍历，需要一个线性的结构。Fiber Tree 采用链表结构（child + sibling + return），使得从任意叶子节点都能恢复遍历——渲染被打断后，下一个时间切片中可以继续。

Fiber Tree 与双缓冲 ​

虚拟 DOM 是树结构，但基于可中断渲染的需求，

React 维护两棵 Fiber 树：

  • current 树：当前屏幕上显示的内容对应的 Fiber 树
  • workInProgress 树：正在内存中构建的新 Fiber 树

两者通过 alternate 指针相互引用。当 workInProgress 树构建完成后，React 通过切换根节点的指针（current 指向 workInProgress 树）完成渲染，这个过程就是双缓冲。好处是：渲染切换是原子的，不会出现半成品 UI；同时复用 Fiber 节点减少内存分配。

调度器 Scheduler ​

React 将一个大的渲染任务拆分为多个小的工作单元（Fiber 节点），每处理完一个单元就检查是否需要让出主线程，保证页面绘制的流畅。

浏览器一帧的工作流程：

  1. 处理事件回调（click、input...）
  2. 处理计时器回调
  3. 开始帧
  4. 执行 requestAnimationFrame 回调
  5. 页面布局计算、合并到主线程
  6. 绘制
  7. 空闲时间执行 requestIdleCallback

调度器的目的，就是利用每一帧最后的空余时间来处理fiber节点。但requestIdleCallback的兼容性差，React 为采用该 api，但借用了这里的思想。react 的任务切片是宏任务，使用 MessageChannel来实现任务调度（而非 setTimeout，因为 setTimeout 递归时最小延迟 4ms，MessageChannel 更快）。同时根据任务的优先级管理执行时机：

优先级场景
立即执行（最高）点击事件、输入框输入
用户阻塞级滚动、拖拽
正常优先级render、列表、动画、网络请求
低优先级分析统计
闲置优先级（最低）console.log 等可延迟任务

调度器中使用小根堆来管理任务优先级，同时通过手动判断何时让出主线程。

协调流程 Reconciliation ​

React 的渲染流程分为两个阶段：

1. Render 阶段（可中断）

从根节点开始，深度优先遍历 Fiber 树，对每个 Fiber 节点执行 beginWork（计算子节点的变更），处理完后执行 completeWork（收集副作用、创建子 Fiber）。此阶段是纯计算，不产生 DOM 操作，可以被中断和恢复。

2. Commit 阶段（不可中断）

将 Render 阶段收集的副作用一次性提交到真实 DOM，分为三个子阶段：

  • BeforeMutation：读取 DOM 快照（getSnapshotBeforeUpdate）
  • Mutation：执行 DOM 插入、更新、删除
  • Layout：执行 useEffect 清理函数、useLayoutEffect 回调、componentDidMount/Update

事件机制 ​

为配合 Fiber 架构中的优先级调度，React 不将事件直接绑定在 DOM 元素上，而是统一委托到 root 节点，通过冒泡机制捕获并处理事件。

  1. 用户与页面交互时，浏览器生成一个原生事件
  2. 事件沿 DOM 树向上冒泡，到达 React 的 root 节点
  3. React 捕获事件后，创建一个 SyntheticEvent（合成事件）实例，根据优先级调度事件处理器
  4. 事件处理完后，SyntheticEvent 不会被销毁，以供下次复用（事件池机制，React 17 后已移除）

合成事件的优势：

  • 跨浏览器一致性：抹平浏览器差异，提供统一的事件接口
  • 优先级调度：不同事件可赋予不同优先级，支持并发渲染
  • 性能优化：事件委托减少 DOM 上的事件监听器数量

Diff ​

Diff 算法对比前后两棵 Fiber 树的差异，标记哪些节点需要新增、更新、移动或删除，以便最小化真实 DOM 的操作。传统地逐节点对比两棵树的时间复杂度为 O(n³)，React 基于以下两个前提将复杂度降为 O(n)：

  1. 跨层级的节点移动非常少，可以忽略
  2. 同一层级的子节点可以通过 key 来标识身份

基于此，React Diff 按三个层级进行策略优化：

Tree 层级 ​

不对跨层级的节点进行比较。如果父节点不同，整棵子树直接销毁重建，不会尝试将子节点移动到其他层级。

jsx
// 旧树：div 下有 span
// 新树：p 下有 span
// React 不会复用 span，而是销毁旧的 div>span，创建新的 p>span

同一位置的组件节点，比较组件类型（type）：

  • 同类型组件：保留节点，继续 diff 子节点，更新 props
  • 不同类型组件：销毁旧组件及其子树，挂载新组件
jsx
// 旧：<Counter />
// 新：<Timer />
// type 不同，销毁 Counter，挂载 Timer

Element 层级 ​

同一层级的子节点列表比较，这是 diff 最复杂的部分：

无 key 时：按索引顺序逐一比较。如果子节点顺序变化，会导致不必要的更新（因为 React 认为索引相同的节点是同一个节点）。

有 key 时：以 key 为节点身份标识，复用 key 相同的节点，只需移动位置。React 使用双端对比的思路，通过 key 在新旧列表中建立映射关系，判断节点是复用、移动还是新增/删除：

jsx
// 旧列表：[A, B, C, D]
// 新列表：[A, C, B, E]

// 有 key 时：
// A 位置不变 → 复用
// C 从索引2移到索引1 → 移动
// B 从索引1移到索引2 → 移动
// D 不在新列表中 → 删除
// E 不在旧列表中 → 新增

// 无 key 时（按索引比较）：
// 索引0：A → A 复用
// 索引1：B → C 更新（误认为同一节点变了）
// 索引2：C → B 更新（误认为同一节点变了）
// 索引3：D → E 更新（误认为同一节点变了）
// 结果：3次无意义的更新，且 D 被删除 E 被新增变成了 D 更新为 E

Immutable ​

在js中，对象是可变的。但这会导致如下的问题。

js
let foo = { a: 1 };
let bar = foo;
foo.a = 2; // 此时bar.a 也变成了2。因为foo和bar使用了相同的引用地址
1
2
3

js如此设计的本意是为了节省内存，但对于大型项目来说，这种隐式的可变性，是灾难的。实践过程中我们可能会使用深拷贝、浅拷贝来解决问题，但这又使得内存空间被浪费。

immutable便解决了这个问题。通过immutable创建的数据便“不可变”。对immutable修改，添加，删除的操作，都会返回新的immutable对象，返回的immutable会尽可能的复用未发生改变的数据。

我们将对象视为一个树，immutable就是一个特殊的不可变的树，是在树中，节点是不可变的。我们操作树的时候，只能创建新的节点来替代发生变化子节点，由于其父节点也是不可变的，所以父节点也需要使用新的节点来替代，即发生变化的子节点向上直至根节点，需要用新创建的节点来代替。

js
import { Map } from "immutable";
let a = Map({
  select: "users",
  filter: Map({ name: "Cam" })
});
let b = a.set("select", "people"); // 返回新的immutable对象

a === b; // false 根节点变化了
a.get("filter") === b.get("filter"); // true filter部分复用了
