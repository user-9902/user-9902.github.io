TCP ​

TCP(传输控制协议, Transmission Control Protocol) 是一种面向连接的、可靠的、基于字节流的传输层通信协议, 广泛应用于互联网中，它旨在提供可靠的端到端通信。

TCP特点 ​

  • 一对一
  • 面向字节
  • 确认机制
  • 超时重传

TCP帧结构 ​

拥塞控制 ​

发送窗口 = min(接收窗口 rwnd, 拥塞窗口 cwnd)

  • 慢开始：连接建立后，拥塞窗口 cwnd 从1个MSS开始，每收到一个确认就翻倍，呈指数增长
  • 拥塞避免：当cwnd达到慢开始门限(ssthresh)后，改为线性增长（每RTT加1个MSS）
  • 快重传：收到3个重复确认后立即重传丢失的报文段，不等超时计时器到期
  • 快恢复：执行快重传后，将ssthresh和cwnd减半，进入拥塞避免阶段（而非慢开始）
cwnd增长示意：
慢开始: 1 → 2 → 4 → 8 → 16 (达到ssthresh)
拥塞避免: 16 → 17 → 18 → 19 → ... (线性增长)
超时丢包: ssthresh = cwnd/2, cwnd = 1, 重新慢开始
3个重复ACK: ssthresh = cwnd/2, cwnd = ssthresh, 进入快恢复

流量控制 ​

发送设备和接收设备处理信息的能力、网络的负载能力都会导致数据传输是否可靠。为此TCP有着一系列控制流量的办法。

  • 滑动窗口机制：接收方在确认帧中通过"窗口"字段告知发送方自己的接收缓冲区剩余大小(rwnd)，发送方据此调整发送速度
  • 零窗口探测：当接收方窗口为0时，发送方定期发送零窗口探测报文，询问接收方窗口是否已恢复
  • 糊涂窗口综合征避免：接收方不通告小窗口，发送方不发送小数据段（Nagle算法）

序号方向

3Server→ ClientFIN=1，ACK=1
4Client → ServerACK=1

保活机制 ​

建立TCP连接的双方长时间无数据交互时，触发保活机制。TCP发送探测报文，若有响应则刷新保活时间，若无响应则断开连接。

  • 默认保活时间：2小时（7200秒）
  • 探测间隔：75秒
  • 探测次数：9次失败后断开

注意：保活机制可能被中间设备（NAT、防火墙）干扰，应用层通常自行实现心跳机制更为可靠。
